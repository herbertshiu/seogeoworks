One market. Two languages. One system.

Hong Kong search is bilingual. English and Traditional Chinese are related markets, not duplicates. This page is the operating model for rankings, hreflang, and citations.

What this page answers

Bilingual SEO matches each search language to its own query intent, URL signals, and proof. Bilingual GEO does the same for answer engines: a source they can quote in the language of the question, without contradicting the other language.

Use this when a Hong Kong brand publishes in English and 繁體中文 and needs one rule for architecture, writing, and measurement. It assumes Google is the primary web index in Hong Kong, and that answer engines reuse the same public facts.

此頁解答甚麼

雙語 SEO 是把每種搜尋語言對上各自的查詢意圖、網址訊號與證明。雙語 GEO 則把同一紀律用在答案引擎：它們能用提問的語言引用你，而且兩種語言的事實不會互相矛盾。

當香港品牌同時以英文與繁體中文發布，並需要一套架構、寫作與量度規則時，用這一頁。前提是 Google 為香港的主要網頁索引，而答案引擎重用的是同一組公開事實。

Two queries, not one translation

Translating a page and swapping the H1 does not cover both markets. The words change, and so does the job the searcher is hiring the page to do.

  • English queries such as “SEO company Hong Kong” often carry international or bilingual-buyer intent: credibility, scope, and whether the team can work in English.
  • Traditional Chinese queries such as 香港 SEO 公司 often carry local comparison intent: who is credible, what the work includes, and what it costs.
  • Keep the facts identical: legal name, place, offer, and proof. Change the examples, the objections, and the order of the answer.
  • Do not translate the legal entity name. Repeat the canonical organization name in both languages so mentions resolve to one entity.

Simplified Chinese is a third market. It belongs on its own URL if you genuinely serve mainland readers or Baidu. It is not the default body copy for Hong Kong.

兩組查詢，不是一次翻譯

把頁面翻譯並換掉 H1，並不能同時覆蓋兩個市場。用字變了，搜尋者要這一頁完成的工作也變了。

  • 英文查詢（例如 “SEO company Hong Kong”）往往帶有國際或雙語買家意圖：可信度、範圍，以及團隊能否以英文工作。
  • 繁體中文查詢（例如 香港 SEO 公司）往往帶有本地比較意圖：誰可靠、工作包含甚麼、收費如何。
  • 事實保持一致：法定名稱、地點、服務與證明。例子、異議與答案的次序則按語言改寫。
  • 不要翻譯法定實體名稱。兩種語言都重複同一規範機構名稱，讓提及能對上同一個實體。

簡體中文是第三個市場。若你確實服務內地讀者或百度，應放在獨立網址。它不是香港頁面的預設正文。

URL architecture search engines can resolve

Pick one model and document it. Mixed signals — a language toggle that also claims two hreflang codes on one URL — are worse than a simple page.

SituationDo this
Both languages acquire customers Separate URLs. Self-canonical each one. Reciprocal hreflang for en, zh-Hant-HK, and x-default.
One language is primary; the other is a reading aid One URL. Set html lang and hreflang to the primary language only, plus x-default. This page uses that model: English is primary.
Simplified Chinese for the mainland A separate URL with zh-Hans. Do not serve it as the Hong Kong default.
  • Do not auto-redirect on IP address or Accept-Language. Offer the other language with a link or a toggle that does not change the canonical.
  • Use zh-Hant-HK when the copy, currency, and examples are Hong Kong-specific. Use zh-Hant when one Traditional Chinese URL serves a wider region.
  • One visible H1. The title and meta description must match the primary language of the URL.
  • Return the alternate language in the HTML, not only inside an image, a PDF, or a button that fetches it later.

搜尋引擎能解析的網址架構

選定一種模型並寫下來。混合訊號——語言切換同時在同一網址宣稱兩個 hreflang——比一個簡單頁面更差。

情況這樣做
兩種語言都要獲客 獨立網址。各自規範網址。互相標註 en、zh-Hant-HK 與 x-default。
一種語言為主，另一種只是閱讀輔助 單一網址。html lang 與 hreflang 只標主要語言，另加 x-default。本頁用此模型：英文為主。
面向內地的簡體中文 獨立網址，語言碼 zh-Hans。不要把它當作香港預設版。
  • 不要按 IP 或 Accept-Language 自動重新導向。用連結或不會改動規範網址的切換提供另一語言。
  • 文案、貨幣與例子都屬香港時，用 zh-Hant-HK。同一繁體頁要覆蓋更廣地區時，用 zh-Hant。
  • 頁面只顯示一個 H1。標題與 meta description 必須與該網址的主要語言一致。
  • 另一語言要在 HTML 裡，不要只放在圖片、PDF，或要稍後才載入的按鈕中。

Writing that can rank and be cited

Answer engines quote the passage that already answers the prompt. A bilingual brand needs that passage twice, with the same facts and different wording.

  1. Open with a one-sentence definition in the first screen. Support it with scope and a limit — what you will not claim.
  2. Write Traditional Chinese the way Hong Kong readers search: 搜尋、公司、收費、代理. Do not leave simplified characters in the body.
  3. Put proof beside the claim: a date, a named scope, a source the reader can open.
  4. Give each money page its own lede, examples, and questions. A shared template with the keyword swapped is not a second language.
  5. Link across languages with descriptive anchors, including the SEO field guides and the English Hong Kong SEO note.

For the citation mechanics that apply in either language, use How to earn citations. For the strategy split underneath both, use SEO vs GEO.

寫得出排名、也引得到用的文字

答案引擎引用的是已經答到問題的段落。雙語品牌需要同一事實的兩段文字，用字不同。

  1. 首屏用一句定義開場，並寫明範圍與界限——你不會宣稱甚麼。
  2. 繁體中文按香港讀者的搜尋方式來寫：搜尋、公司、收費、代理。正文不要留下簡體字。
  3. 證明放在主張旁邊：日期、具名範圍、讀者打得開的來源。
  4. 每個獲客頁都要有自己的導語、例子與問題。只換關鍵字的共用模板，不是第二種語言。
  5. 用描述性錨點跨語言連結，包括 SEO 專題 與 英文香港 SEO 筆記。

兩種語言都適用的引用方法，見 如何賺取引用。兩者底下的策略分別，見 SEO 對比 GEO。

How answer engines choose a language

They answer in the language of the question. If the only crisp definition of your brand is in English, a Traditional Chinese prompt is more likely to name a source that already explained you in Chinese — often a competitor or a directory.

  • Corroboration should exist in the same language. A Chinese directory listing does not, by itself, support an English definition. The reverse is also weak.
  • Keep one set of entity facts: name, address, founders, offers. Language-specific pages describe those facts; they do not invent a second company.
  • Once a month, run a fixed prompt list in both languages. Record who is named, which URL is cited, and whether the description matches the site.
  • Pair that with classic SEO health: crawl, indexation, and the GEO readiness checklist.

答案引擎如何選擇語言

它們用提問的語言作答。若品牌唯一清晰的定義只在英文，繁體中文的提問更可能點名一個已經用中文解釋你的來源——往往是競爭者或名錄。

  • 佐證應存在於同一語言。中文名錄本身支持不了英文定義。反過來同樣弱。
  • 實體事實只保留一套：名稱、地址、創辦人、服務。不同語言的頁面是描述這些事實，而不是發明第二間公司。
  • 每月用固定提示清單跑兩種語言。記錄被點名的是誰、引用了哪條網址、描述是否與網站一致。
  • 同時保持傳統 SEO 健康：爬取、索引，以及 GEO 準備清單。

A 30-day operating list

  1. Week 1 — architecture. Inventory indexable URLs. Choose one-URL or two-URL. Fix canonicals, html lang, and hreflang. Remove IP redirects.
  2. Week 2 — the five money pages. Rewrite the lede, examples, and questions in both languages. Native-edit anything drafted by a model.
  3. Week 3 — entity alignment. Make the organization name, address, and offer match on the site, profiles, and the pages you want cited.
  4. Week 4 — measurement. In Search Console, filter Performance to Hong Kong and separate Latin-script queries from Chinese queries. Run ten prompts per language and save the named sources.

30 日操作清單

  1. 第 1 週 — 架構。 盤點可索引網址。選定單網址或雙網址。修正規範網址、html lang 與 hreflang。移除 IP 重新導向。
  2. 第 2 週 — 五個獲客頁。 兩種語言都重寫導語、例子與問題。模型起草的文字要經母語編輯。
  3. 第 3 週 — 對齊實體。 讓機構名稱、地址與服務在網站、簡介，以及你希望被引用的頁面上一致。
  4. 第 4 週 — 量度。 在 Search Console 把成效篩到香港，並把拉丁字母查詢與中文查詢分開。每種語言跑十條提示，保存被點名的來源。

What to avoid

  • Publishing machine translation with no native edit.
  • Pointing en and zh-Hant hreflang at one URL.
  • Stuffing both languages into a single title tag.
  • Using simplified characters as the Hong Kong body copy.
  • Treating a Baidu result and a Google.hk result as the same ranking.

應避免的做法

  • 發布未經母語編輯的機器翻譯。
  • 把 en 與 zh-Hant 的 hreflang 指向同一網址。
  • 在單一 title 標籤塞進兩種語言。
  • 用簡體字作為香港正文。
  • 把百度結果與 Google.hk 結果當成同一種排名。

Questions operators ask

Should a Hong Kong site use one URL or two?

Use two URLs when both languages are meant to acquire customers. Give each URL its own canonical and reciprocal hreflang (en, zh-Hant-HK, and x-default). Use one URL only when one language is primary and the other is a reading aid. Do not point two hreflang language codes at the same URL.

Is machine translation enough?

No. It can draft. A native editor has to fix terminology, intent, and examples. Unedited translation is how a brand gets cited for an offer it does not sell.

Which language code should Hong Kong Traditional Chinese use?

Use zh-Hant-HK when the copy, currency, and examples are specifically Hong Kong. Use zh-Hant when the same Traditional Chinese page targets a wider region. Use zh-Hans only on a separate Simplified URL.

Does GEO change the bilingual model?

It raises the cost of having only one language. Answer engines reply in the language they were asked in. The facts must match, and each language needs its own quotable passage.

營運者常問的問題

香港網站應用一個網址還是兩個？

兩種語言都要獲客時，用兩個網址。各自有規範網址，並互相標註 hreflang（en、zh-Hant-HK 與 x-default）。只有一種語言為主、另一種只是閱讀輔助時，才用單一網址。不要把兩個 hreflang 語言碼指向同一網址。

機器翻譯夠不夠？

不夠。它可以起草。母語編輯仍要修正用語、意圖與例子。未經編輯的翻譯，會讓品牌被引用成它並不出售的服務。

香港繁體中文應用哪個語言碼？

文案、貨幣與例子都屬香港時，用 zh-Hant-HK。同一繁體頁面向更廣地區時，用 zh-Hant。zh-Hans 只用在獨立的簡體網址。

GEO 會不會改變雙語模型？

它提高了只做一種語言的代價。答案引擎用提問的語言回覆。事實必須一致，每種語言都要有自己可被引用的段落。
